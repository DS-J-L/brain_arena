# 피의 게임·더 지니어스 추가 게임 조사

조사일: 2026-10-27 · 대상: Brain Arena의 친구 초대형 1대1 웹 게임

## 1. 추천 결론

**빠르게 추가하려면 ‘같은 그림 찾기’, 새로운 전략 경험을 더하려면 ‘컬러턴’을 우선 추천한다.** 그다음은 기존 흑과 백의 자원 관리 확장판인 ‘흑과백2’, 공개 정보만으로 수를 겨루는 ‘십이장기’다.

| 목적 | 추천 게임 | 추천 이유 |
|---|---|---|
| 첫 추가 게임을 작게 완성 | 같은 그림 찾기 | 기존 카드 뒤집기·공개 시간·기억 게임 화면을 활용할 여지가 크다 |
| 현재 목록에 없는 재미 추가 | 컬러턴 | 말 이동, 숨은 지뢰, 색 전환을 결합한 보드 전략이다 |
| 기존 심리전의 깊이 확장 | 흑과백2 | 일회용 숫자 타일 대신 총예산을 배분하는 다른 의사결정이 생긴다 |
| 장기적으로 반복할 전략 종목 | 십이장기 | 숨은 정보와 운에 의존하지 않는 소형 보드 대결을 추가한다 |

‘같은 숫자 찾기’는 현재 **숫자를 찾아라**와 핵심 방식이 겹치므로 신규 게임으로 세지 않는 편이 좋다. ‘모노레일’은 매력적이지만 불가능 선언 처리와 반복 플레이의 수 싸움을 먼저 검토해야 한다.

이 우선순위는 아래 방송 자료와 저장소 구조를 비교한 **기획 판단**이다. 재미·소요 시간·개발 난이도는 플레이테스트나 구현으로 검증한 값이 아니다.

## 2. 조사 범위와 근거 해석

더 지니어스 한국판과 피의 게임 시즌 1~3에서 현재 서비스에 맞는 종목을 선별했다. 전 회차의 게임을 빠짐없이 나열하는 목록은 아니다. 피의 게임X와 해외판의 별도 게임은 이번 추천 대상에서 제외했다.

- **방송 핵심 규칙:** 출처에서 확인한 진행 방식만 요약했다. 방송의 세부 예외까지 확정한 구현 명세는 아니다.
- **온라인 제안:** 동일 출발 조건, 시간 제한, 반복 상태 처리 등 Brain Arena에 적용하기 위한 변경안이다.
- **확인 수준 A:** 방송사·프로그램의 공개 규칙에서 핵심 방식을 확인했다.
- **확인 수준 B:** 기사·팬 위키의 규칙 정리로 확인했다. 구현 전 공식 룰 영상과 대조할 필요가 있다.
- **확인 수준 C:** 등장과 대략적인 콘셉트만 확인했다. 정확한 규칙을 확보하기 전에는 개발 대상으로 확정하지 않는다.

피의 게임2는 Contents Wavve 저작권 고지가 있는 [일본어 프로그램 사이트](https://www.bloody-game.com/)에서 컬러턴과 수식 로드의 규칙을 확인했다. 일본어 설명을 한국어로 요약했으며, 접근되지 않은 하위 페이지는 확인한 것으로 취급하지 않았다. 더 지니어스의 일부 상세 규칙은 팬 위키를 보조 자료로 사용했다.

| 배틀 오름차순 | 두 카드 선택·분배, 비공개 개인 보드 배치 | 단순 숫자 정렬 게임은 신규성 낮음 |

## 5. 우선 추천 게임 상세

### 5.1 같은 그림 찾기 — 첫 추가 후보

**방송 핵심 규칙:** 알파벳 뒤에 서로 다른 그림이 숨겨져 있고, 개인 컨베이어 벨트의 다음 그림과 일치하는 위치를 찾으며 전진한다. 정답이면 전진하고 추가 확인 기회를 얻으며, 오답이면 벨트가 후진하면서 상대 차례가 된다. 먼저 끝에 도달하면 승리하고 벨트에서 떨어지면 패배한다. 출발 위치는 시즌마다 다르다. [같은 그림 찾기 규칙 정리](https://m.namu.moe/w/같은%20그림%20찾기) [G1]

**추가 가치:** 숫자를 찾아라는 기억과 계산을 함께 요구하지만 이 게임은 그림 기억과 정보 공개 순서에 집중한다. 수식 게임이 부담스러운 사람도 진입하기 쉽다는 가설을 검증할 만하다.

**온라인 제안:** 16개 그림 패널과 동일 출발점을 사용한다. 컨베이어 벨트의 전진·후진을 실제 상태로 구현하고 단순 정답 점수제로 대체하지 않는다. 선공을 교대한 두 판의 결과를 비교하는 방식은 선택 사항으로 검토한다.

**구현 포인트:** 기존 `MemoryCard`의 뒤집기 표현은 참고할 수 있지만 현재 숫자·연산자 타입에 맞춰져 있어 그림 카드로 확장이 필요하다. 서버가 패널 매핑·벨트·덱을 보관하고 공개 중인 그림만 전송한다. 한 번 공개한 그림은 브라우저가 이미 받은 정보이므로 다시 숨겨도 외부 기록을 막을 수는 없다.

**착수 전 결정:** 정답 후 추가 확인 기회의 정확한 범위, 패널 노출 시간, 벨트 보충 순서, 제한 시간 초과를 오답으로 처리할지 여부. 봇은 관측한 그림을 기억하는 별도 메모리가 필요하며 완벽 기억만 제공하지 않도록 난이도를 조절한다.

### 5.2 컬러턴 — 장르 확장 효과가 큰 후보

**방송 핵심 규칙:** 각자 흑색 또는 백색 칩 7개를 받고 첫 줄에 투입한다. 칩은 상하좌우·대각선으로 한 칸 이동하며 상대 색도 움직일 수 있다. 숨은 지뢰 칸에서는 색이 바뀐다. 지뢰는 한 줄에 3개씩 총 18개이고 직전에 움직인 칩은 다음 수에서 움직일 수 없다. 자기 색 4개를 나란히 만들면 승리한다. [프로그램 공개 규칙](https://www.bloody-game.com/カラーターン) [B1]

**추가 가치:** 기존 일곱 게임에 없는 ‘공동 공간에서 상대 말도 이용하는 수 싸움’을 제공한다. 지뢰를 추론하고 상대 색을 바꾸는 선택이 있어 단순 사목과도 구분된다.

**온라인 제안:** 투입 위치 선택 → 이동 경로 미리보기 → 확정 → 색 전환·승패 확인 순서로 진행한다. 색 외에 문양을 함께 표시한다. 반복 상태와 전체 수 제한을 두고, 도달 시 무승부로 끝내는 규칙을 제안한다.

**구현 포인트:** 말은 색과 별개인 고유 ID를 가져야 직전 이동 제한을 정확히 적용할 수 있다. 서버에만 지뢰 지도를 보관하고 봇도 실제 지뢰 위치를 직접 읽지 않는다. 공개된 색 전환 결과는 봇과 양쪽 플레이어가 동일하게 관측한다.

**착수 전 결정:** 첫 줄이 각 플레이어 기준 어느 쪽인지, 투입도 한 수인지, 점유 칸 이동 가능 여부, 양쪽 사목이 동시에 완성될 때 판정, 지뢰 효과의 재방문 처리, 직전 이동 제한이 색 전환 뒤에도 유지되는 방식. 공개 페이지의 그림·공식 영상과 대조해야 한다. 무작위 지뢰는 양쪽 대칭 조건을 시험하되, **대칭만으로 선후공 공정성이 증명되지는 않는다.**

### 5.3 흑과백2 — 예산 배분 심리전

**방송 핵심 규칙:** 각자 99포인트를 가지고 최대 9라운드를 겨룬다. 선공 제출 뒤 후공이 선택하며, 낸 수가 한 자리인지 두 자리인지 색으로 표시된다. 더 많이 낸 쪽이 승점을 얻고 사용 포인트는 소모된다. 상대 잔여 포인트는 정확한 수치 대신 20포인트 단위 표시등으로 추정한다. [방송 규칙 정리](https://endlesschallengerspoiuy3.tistory.com/50) [G2]

**추가 가치:** 현재 흑과 백의 ‘남은 0~8 타일 중 선택’과 달리, 지금 크게 쓰고 이길지 뒤 라운드 예산을 남길지 선택한다. 같은 이름 계열이어도 별도 엔진이 필요한 이유다.

**온라인 제안:** 숫자 입력·증감 버튼과 제출 확인을 제공한다. 자기 잔여 예산은 정확히 보여주고 상대는 표시등으로만 보여준다. 서버가 선공 제출 직후 색과 갱신된 표시등을 함께 전송한다.

**구현 포인트:** 현재 `tileColor()`는 홀짝을 색으로 변환하므로 재사용하면 규칙이 틀린다. `remainingTiles`를 예산으로 바꾸고 상대의 과거 실제 입찰액이 기록에서 새지 않도록 한다. 연습 봇은 표시등과 승패로 가능한 상대 예산 범위를 추정한다.

**착수 전 결정:** 0 제출, 같은 수 제출 시 승점, 다음 선공 결정, 9라운드 동점, 표시등 구간 경계와 예산 0 표시. 방송 자료로 확정되지 않는 예외는 서비스 규칙으로 명시한다.

### 5.4 십이장기 — 운보다 수 읽기에 집중하는 후보

**방송 핵심 규칙:** 12칸 보드에서 왕·장·상·자를 움직이며 대결한다. 말별 이동 방향, 상대 말 포획과 재투입, 자의 승격, 왕 포획·진영 진입 조건이 핵심이다. [십이장기 규칙 정리](https://www.namu.moe/w/십이장기) [G3]

**추가 가치:** 현재 목록에서 부족한 공개 정보 보드게임이다. 게임 중 정보를 잠깐 외우거나 부저를 먼저 누르는 능력보다 수 읽기를 겨루는 선택지를 만든다.

**온라인 제안:** 말 선택 시 이동 가능한 칸과 재투입 가능한 칸을 표시한다. 반복 상태는 무승부로 처리하고 선후공 교대 재경기를 제공하는 안을 검토한다.

**구현 포인트:** 말의 방향을 플레이어 기준으로 계산하고 포획·소유자 변경·재투입·승격을 하나의 서버 판정 흐름으로 묶는다. 공개 정보라 숨은 데이터 분리는 단순하지만 합법 수와 종료 조건은 엄밀해야 한다. 봇은 제한 깊이 탐색으로 시작할 수 있다.

**착수 전 결정:** 왕의 진영 진입이 언제 승리로 확정되는지, 왕을 잡힐 위치로 이동할 수 있는지, 반복 상태 계산에 차례·보유 말이 포함되는지, 재투입 제한. 동물장기 등 유사 게임의 규칙을 방송 규칙과 혼합하지 않는다.

## 6. 후속·조건부 후보

### 기억의 미로

보이지 않는 벽의 위치를 시행착오로 기억하며 목적지에 먼저 도착하는 대결이다. 지니어스 S3의 등장과 기본 콘셉트는 [IT동아의 게임 분석](https://it.donga.com/22206/)에서 확인했다. [G4]

기억을 공간 탐색과 결합한다는 점에서 적합하다. 다만 벽 발견의 노출 시간, 한 턴 이동 수, 충돌 후 처리, 아이템 규칙은 공식 영상으로 확정해야 한다. 온라인용 무작위 맵은 양쪽 목적지 도달 가능성과 최단 경로 길이를 검사하고, 선후공을 바꾼 동일 맵 두 판도 시험할 만하다. 봇은 관측한 벽만 알아야 한다. 숨은 벽 생성·공정성 검사와 이동 재생이 필요해 1차 후보보다 비용이 크다.

### 모노레일

직선·꺾임 철로를 한 턴에 1~3개 놓아 이미 놓인 모든 철로가 하나의 순환선이 되게 만든다. 완성하면 이기며, 불가능을 선언하면 상대가 남은 타일로 완성 가능성을 입증해야 한다. S3·S4 등장과 규칙은 [팬 위키](https://the-genius-show.fandom.com/wiki/Monorail)에 정리되어 있다. [G5]

**불가능 여부를 서버가 즉시 계산해 알려주면 추론과 블러핑의 일부가 사라진다.** 상대가 제한 시간 안에 완성 배치를 제출하는 별도 입증 단계가 더 적합하다. 타일 소진·복수 고리·고립 철로도 처리해야 한다. 고정 시작 배치의 정형화된 수순이 반복 플레이를 약화할 가능성이 있어 테스트 후 판단한다. 시작 배치 변형은 방송 규칙과 구분한 실험 모드로만 검토한다.

### 양면포커

양면에 다른 숫자가 있는 카드를 이용하는 베팅 게임이다. [팬 위키](https://the-genius-show.fandom.com/wiki/Double_Sided_Poker)의 S3 소개와 [tvN 공식 영상의 S4 양면포커 구간](https://www.youtube.com/watch?v=uU-m1XivK44&t=8744s)으로 등장 사실을 확인했다. [G6]

인디언 포커의 칩 이동·베팅 검증을 참고할 수 있지만 카드 양면의 공개 대상과 승부 규칙까지 같은 것은 아니다. 카드 조합, 공개 단계, S3와 S4 차이, 동점·폴드·올인 규칙을 먼저 고정해야 한다. 기존 포커와 장르가 겹치므로 보드 전략 후보 다음 순위가 적절하다.

### 미스터리 넘버

상대 숫자 블록을 맞히는 피의 게임2 데스매치라는 점은 [스포츠경향 기사](https://sports.khan.co.kr/article/202305170032003)에서 확인했다. [B3]

추리 장르를 보완할 가능성이 있지만 이번 조사에서는 숫자 범위·중복 허용·질문 종류·공개 피드백을 확정할 근거를 확보하지 못했다. 따라서 숫자야구나 마스터마인드의 규칙을 그대로 붙여 방송 게임인 것처럼 구현해서는 안 된다. 공식 룰 확보 뒤 2인 대전과 후보 집합 기반 봇의 난이도를 산정한다.

### 수식 로드

숫자·연산·길이 그려진 카드를 6×6 보드에서 연결해 100을 만드는 팀 게임이다. 수색 단계가 있고 카드를 회전해서 쓰는 것은 금지한다. [프로그램 공개 규칙](https://www.bloody-game.com/複製-ジャングル迷路-2)에서 확인했다. [B2]

온라인에서는 수색을 공개 카드 드래프트로 바꾸고 각자 보드에서 경로·수식을 완성하는 안을 시험할 수 있다. 이는 **방송 원형을 바꾼 1대1 변형안**이다. 현재 수식 판정은 숫자 두 개와 연산자 하나 중심이라 긴 수식, 숫자 연결, 연산 우선순위, 경로 연결 검증을 별도로 만들어야 한다. 양쪽이 완성 가능한 카드 구성인지 검사할 필요도 있어 초기 후보보다 비용이 크다.

### 아트경매

피의 게임3의 4인 결승에 등장하며 경매와 담보 활용이 중요했다는 점은 [결승 보도](https://v.daum.net/v/20250120132535841?s=print_news)에서 확인했다. 명화 기억·문제 풀이와 결합된 구조는 [회차 규칙 정리](https://d.namu.moe/w/피의%20게임3/11-12일차)를 보조 근거로 삼았다. [B4]

기억과 자원 경쟁의 결합은 매력적이지만 2인 경매의 전략이 원형과 다르고 자산 우위가 누적될 가능성이 있다. 정확한 담보·오답·정산 규칙을 확인한 뒤 실험해야 한다. 이미지와 설명 데이터도 별도로 준비해야 하므로 단기 후보로 추천하지 않는다.

### 진실탐지기

네 자리 패스워드에 대한 질문에 거짓으로 답하고, 진실을 답하면 패널티로 정보를 공개하는 추리 게임이다. [규칙 정리](https://www.namu.moe/w/진실탐지기)에서 확인했다. [G7]

자유 문장 질문을 서버가 정확하게 판정하는 문제가 크다. ‘특정 자리 숫자가 5 이상인가’ 같은 정형 질문으로 제한하면 구현할 수 있으나 자유 질문의 재미가 바뀐다. 별도 질문 체계의 재미를 검증하기 전까지 보류한다.

## 7. 별도 추가를 권하지 않는 게임

**같은 숫자 찾기:** 16개 위치의 숫자·연산자를 기억하고 부저를 누른 뒤 숫자→연산자→숫자로 목표값을 만드는 방식이다. [방송 규칙 정리](https://m.namu.moe/w/같은%20숫자%20찾기)와 현재 [숫자를 찾아라 규칙](../rules/number-game-rule.md)을 비교하면 핵심 경험이 같다. [G8] 암기 시간·승리 점수·공개 방식은 다를 수 있으므로 동일한 세부 구현이라고 단정하지 않는다. 기존 게임의 짧은 암기 시간·고난도 옵션으로 검토하는 편이 낫다.

**다인 협상·연합 게임:** 먹이사슬, 콩의 딜레마 같은 메인매치는 사람 사이의 역할·팀·연합이 재미의 핵심이다. 2인으로 축소하면 다른 게임이 되기 쉽다. tvN의 [S1 회차 소개](https://tvn.cjenm.com/ko/thegenius/episodes/)와 [S2 공식 규칙](https://tvn.cjenm.com/ko/thegenius2/contents1/)에서도 다인 팀·투표 구조를 확인할 수 있다. 이런 종목은 방 인원, 팀별 비공개 정보, 차례, 탈락 후 흐름을 확장하는 별도 제품 단계에서 검토한다.

## 8. 권장 도입 순서와 구현 범위

1. **같은 그림 찾기:** 기억 패널·벨트·봇 관측 메모리를 구현하고 초보자에게 규칙 전달이 쉬운지 확인한다.
2. **컬러턴:** 공간 보드 UI와 색 전환 판정을 추가하고 2인 플레이로 반복·무승부·선공 이점을 검토한다.
3. **흑과백2:** 예산과 정보 공개 규칙을 고정한 뒤 기존 흑과 백과 구분되는 전략이 나오는지 확인한다.
4. **십이장기:** 이동·포획·재투입·반복 판정을 검증하고 초급 탐색 봇을 붙인다.
5. **기억의 미로 또는 모노레일:** 맵·입증 단계 중 더 반응이 좋은 쪽을 후속 실험한다.

실제 일정은 별도 산정한다. 기존 게임의 엔진 하나만 추가하면 끝나는 구조가 아니므로 다음 연결 지점을 함께 반영해야 한다.

| 연결 지점 | 현재 파일 | 신규 게임에서 할 일 |
|---|---|---|
| 게임 ID·화면 타입·소개 | `packages/shared/src/types.ts` | `GAME_TYPES`, `GameView`, `GAME_INFO` 확장 |
| 엔진 | `apps/server/src/games/` | 초기화·합법 행동·상태 전이·개별 뷰·결과 구현 |
| 방 흐름 | `apps/server/src/rooms/roomManager.ts` | 초기화·행동·결과·뷰·시간 초과 분기 연결 |
| 소켓 입력 | `apps/server/src/socket/handlers.ts` | 신규 행동이 현재 검증·인증 흐름을 통과하는지 확인 |
| 화면·규칙 | `apps/web/src/pages/RoomPage.tsx`, `apps/web/src/components/RuleModal.tsx` | 게임 화면·헤더·결과·설명 연결 |
| 연습 모드 | `apps/server/src/bots/practiceBot.ts` | 공개 정보만으로 행동하고 필요한 관측 기억 추가 |
| 규칙 문서 | `docs/rules/` | 방송 근거와 서비스 추가 규칙 구분 |

게임별 검증에서는 정상 승패 외에도 **정보 노출 경계, 중복·지연 제출, 시간 초과, 기권·재접속, 종료 후 행동 차단**을 확인한다. 카드·칩·예산 수량 보존과 보드 종료 조건을 엔진 테스트로 검증하고 기존 `npm test`, `npm run build`를 통과시킨다. 이번 변경은 조사 문서만 작성하므로 게임 구현·플레이테스트·성능 측정을 수행한 결과는 포함하지 않는다.

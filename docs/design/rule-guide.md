# 게임 설명서 개편 설계 — 그림으로 보는 규칙

> 상태: 설계안 (구현 전) · 대상: `apps/web/src/components/RuleModal.tsx`

## 1. 지금 무엇이 불친절한가

현재 규칙 모달은 게임마다 `제목 + 긴 문장 목록`만 있습니다. 내용은 정확하지만 처음 하는 사람에게는 아래 문제가 있습니다.

| 문제 | 예시 |
|---|---|
| **글만 있다** | 결! 합!의 "각 속성이 모두 같거나 모두 달라야 합"은 타일 3장을 한 번 보여주면 끝나는 설명인데 두 문장으로 풀어 씀 |
| **한 줄에 규칙이 여러 개** | 결! 합! "결! 합!과 점수" 첫 항목에 시간·선택·자동 제출·해제가 한 문장에 섞여 있음 |
| **목표가 묻힌다** | 승리 조건이 첫 섹션 중간 문장에 있음. "뭘 하면 이기는지"를 3초 안에 알 수 없음 |
| **진행 순서가 안 보인다** | 아틀라스 "제출 → 공개 → 큰 수부터 올리기 → 무너짐 → 벌점"이 4개 섹션에 흩어져 있음 |
| **세부 규칙과 핵심 규칙이 같은 무게** | 인디언 포커의 "시간 초과 시 자동 콜/폴드"와 "상대 카드만 보인다"가 같은 크기의 bullet |
| **빠진 설명** | 시크릿 다이스에서 **누가 비공개 숫자를 몇 개 내는지**가 규칙에 없음 (엔진: 1개 고정 → 공격 2·수비 2, 2개 고정 → 공격 1·수비 2, 3개 고정 → 1·1) |

## 2. 목표

1. **3초 안에 목표를 안다** — 열자마자 "무엇을 하면 이기는가"와 대표 그림 하나.
2. **30초 안에 한 판의 흐름을 안다** — 단계별 그림 + 짧은 설명을 넘겨 보기.
3. **필요할 때 정확한 규칙을 찾는다** — 지금의 상세 문장은 지우지 않고 "전체 규칙"으로 보존.

## 3. 핵심 결정: 이미지는 "실제 게임 컴포넌트 + 예시 데이터"로 그린다

PNG 스크린샷 대신, 게임 화면에서 쓰는 컴포넌트에 **고정된 예시 데이터**를 넣어 렌더링합니다.

| 방식 | 장점 | 단점 |
|---|---|---|
| **실제 컴포넌트 재사용 (채택)** | 게임 UI가 바뀌면 설명서도 자동으로 따라감 (예: 아틀라스 블록 1~7 → 0~6 변경 시 스크린샷이면 전부 다시 찍어야 함). 용량 0, 다크 테마·모바일에서 선명. 그림 속 글자도 텍스트라 접근성 OK | 예시 데이터를 손으로 작성해야 함 |
| PNG/GIF 스크린샷 | 만들기 쉬움 | 규칙·UI 바뀔 때마다 조용히 낡음. 모바일에서 글자 깨짐. 번들 증가 |
| 별도 일러스트 SVG | 자유로운 표현 | 게임 화면과 모양이 달라져 오히려 헷갈림. 그릴 비용 큼 |

재사용할 수 없는 그림(순환 연속 다이얼, 패스 흐름도, 족보 사다리 등)만 작은 인라인 SVG/CSS로 따로 그립니다.

### 재사용 대상 (지금은 파일 내부 함수라 `export` 필요)

| 컴포넌트 | 위치 | 쓰는 곳 |
|---|---|---|
| `HapBoard`, `HapShape`, `Checks` | `components/GyeolHapGame.tsx` | 결! 합! 1·2 |
| `Giant` | `components/AtlasGame.tsx` | 아틀라스 |
| `PlayingCardFace` | `components/MemoryHoldemGame.tsx` | 메모리 홀덤, 인디언 포커(카드 모양) |
| `MemoryCard` | `components/MemoryCard.tsx` (이미 export) | 숫자를 찾아라, 메모리 홀덤 |
| `Board` | `pages/RoomPage.tsx` → `components/AscendingBoard.tsx`로 분리 | 배틀 오름차순 |
| `.tile.black/.white`, `.die`, `.poker-card` | CSS 클래스 | 흑과 백, 시크릿 다이스, 인디언 포커 |

그림 안의 컴포넌트는 `<GuideFigure>` 래퍼로 감싸 **클릭 불가(`inert`) + 축소(scale)** 처리하고, 그림 전체에 텍스트 대체 설명(`aria-label`)을 붙입니다.

## 4. 새 모달 구조

```
┌──────────────────────────────────────────────┐
│ HOW TO PLAY                               ×  │
│ 아틀라스의 형벌      [2~4인] [10~15분] [보통]  │
│ ┌────────────┬────────────┬──────────────┐   │
│ │ 한눈에 보기 │  진행 순서  │   전체 규칙   │   │  ← 탭
│ └────────────┴────────────┴──────────────┘   │
│                                              │
│  (탭 내용)                                    │
│                                              │
│ [ 규칙을 확인했습니다 ]                         │
└──────────────────────────────────────────────┘
```

### 탭 1 — 한눈에 보기
- **대표 그림 1장** (게임의 핵심 장면)
- **목표** 한 줄 · **승리 조건** 한 줄 (아이콘 🎯 / 🏆 대신 기존 톤에 맞춘 라벨 `GOAL` `WIN`)
- **꼭 알아야 할 것 3가지** — 이것만 알면 첫 판을 할 수 있는 규칙

### 탭 2 — 진행 순서 (스텝퍼)
- 한 번에 한 단계: `그림 + 제목 + 설명 1~2줄`
- 하단 `← 이전 · ● ● ○ ○ · 다음 →`, 키보드 ←/→ 지원, 모바일은 좌우 스와이프
- 단계 수는 게임당 4~6개

### 탭 3 — 전체 규칙
- 현재 `RuleSection` 문장을 그대로 옮김 (정확한 규칙의 원본)
- 섹션을 아코디언으로 접기 — 데스크톱은 기본 펼침, 모바일은 첫 섹션만 펼침
- 중요한 계산 규칙에는 **예시 박스**(그림 포함)를 끼워 넣음 (예: 아틀라스 무너짐, 인디언 포커 폴드 페널티)

### 어디서 열면 어떤 탭부터?
| 진입점 | 기본 탭 | 이유 |
|---|---|---|
| 홈 "규칙 자세히 보기" | 한눈에 보기 | 처음 보는 사람 |
| 대기실 "규칙" | 진행 순서 | 시작 직전 흐름 확인 |
| 게임 중 / 결과 화면 "규칙" | 전체 규칙 | 특정 규칙을 찾으려는 사람 |

`RuleModal`에 `initialTab` prop을 추가해 구현합니다.

## 5. 데이터 구조

규칙이 지금 `RuleModal.tsx` 한 파일(75줄, 문장이 한 줄에 몰려 있음)에 들어 있어 그림까지 넣으면 감당이 안 됩니다. 게임별 파일로 나눕니다.

```
apps/web/src/guide/
  types.ts            GameGuide 타입
  GuideModal.tsx      탭·스텝퍼·아코디언 (RuleModal 대체)
  GuideFigure.tsx     그림 래퍼 (inert, scale, 캡션, 번호 콜아웃)
  figures/            재사용 불가한 그림 (CircularStraight, PassFlow, HandRanking …)
  games/
    atlas.tsx  blackAndWhite.tsx  ascending.tsx  secretDice.tsx
    indianPoker.tsx  findTheNumber.tsx  gyeolHap.tsx  memoryHoldem.tsx
  index.ts            Record<GameType, GameGuide>
```

```ts
interface GuideStep { title: string; body: string; figure: ReactNode; figureLabel: string }
interface RuleSection { title: string; items: string[]; example?: { title: string; body: string; figure?: ReactNode } }

interface GameGuide {
  overview: { figure: ReactNode; figureLabel: string; goal: string; win: string; essentials: [string, string, string] };
  steps: GuideStep[];      // 4~6개
  rules: RuleSection[];    // 현재 문장 그대로 + 선택적 예시
}
```

`Record<GameType, GameGuide>`로 두면 새 게임을 추가할 때 설명서를 빼먹으면 타입 에러가 납니다.

## 6. 게임별 그림 설계

표기: **[대표]** = 한눈에 보기 그림, **①②…** = 진행 순서 단계, **[예시]** = 전체 규칙 안 예시 박스.

### 흑과 백
- **목표** 상대보다 큰 숫자를 내 먼저 5점 · **승리** 5점 선취 또는 9라운드 후 고득점
- **[대표]** 0~8 타일 9장 한 줄 — 짝수 검정, 홀수 흰색 (`.tile.black/.white`)
- ① 내 타일 9장: 짝수=검정, 홀수=흰색, 한 번씩만
- ② 선공이 비공개로 냄 → 후공에게는 **색만** 보임 (뒷면 흰 타일 + "흰색이네?" 말풍선)
- ③ 후공이 냄 → 큰 수가 1점 (7 vs 4 → 선공 +1)
- ④ 이긴 사람이 다음 선공
- **[예시] 추리해 보기** — "상대가 흰색 → 1·3·5·7 중 하나. 8을 내면 확실히 이기지만 가장 센 카드를 쓰게 된다"

### 배틀 오름차순
- **목표** 10칸 보드에 가장 긴 오름차순 만들기
- **[대표]** 완성 보드 `3 5 5 8 2 4 6 7 9 1`, `2→4→6→7→9`(길이 5) 라임 강조 (`Board` + `highlightIndices`)
- ① 카드 두 장 공개 (7, 3)
- ② 선택권자가 한 장, 남은 한 장은 상대에게 (화살표)
- ③ 각자 빈칸 하나에 비공개 배치 — 놓으면 못 옮김
- ④ 선택권은 매 턴 교대, 10턴 뒤 비교
- **[예시] 연결 판정** — `2→2→5` ✓ 길이 3 / `5→3` ✕ 끊김

### 시크릿 다이스
- **목표** 12칸 점수판을 채워 총점이 높은 쪽이 승리
- **[대표]** 최종 주사위 5개 — 고정한 공개 주사위(라임 테두리) + 공격자 숫자 + 수비자 숫자를 색으로 구분
- ① 공개 주사위 3개 → 공격자가 1~3개 고정 (3개 고정은 게임당 1번)
- ② **둘 다 비공개로 숫자 제출** — 개수 표를 그림으로:

  | 고정 | 공격자 | 수비자 |
  |---|---|---|
  | 1개 | 2개 | 2개 |
  | 2개 | 1개 | 2개 |
  | 3개 | 1개 | 1개 |

  (이 표는 현재 규칙 텍스트에 없음 → 전체 규칙에도 추가)
- ③ 동시 공개 → 공격자가 점수 칸 하나 선택 (조건 미달 칸은 0점)
- ④ 공격/수비 교대
- **[예시] 순환 연속** — 1~6을 시계 모양으로 배치한 다이얼, `4-5-6-1-2` 호를 강조 (신규 SVG `CircularStraight`)

### 인디언 포커
- **목표** 상대 칩을 모두 가져오기 (각자 20칩)
- **[대표]** 포커 테이블: 내 카드는 뒷면 `?`, 상대 카드는 앞면 `7` — "내 카드는 나만 못 본다"
- ① 기본 베팅 1칩씩
- ② 상대 카드와 상대 행동으로 내 카드를 추리
- ③ 행동 4가지 칩 — 콜(맞추고 공개) · 레이즈(+1) · 폴드(포기) · 올인
- ④ 공개, 큰 수가 판돈 / 같으면 이월
- **[예시] 폴드 페널티** — 두 장면: `내 9 > 상대 6 인데 폴드 → 건 3칩 + 추가 3칩 = 6칩` / `내 10 폴드 → 추가 10칩`. 둘 다 해당되면 큰 쪽 하나만

### 숫자를 찾아라
- **목표** 목표 숫자를 만드는 카드 3장을 먼저 찾기 · **승리** 6점 (3인 이상 5점)
- **[대표]** 4×4 보드, 목표 `18`, `6 × 3` 세 칸에 선택 순번 1·2·3 (`MemoryCard`)
- ① 20초 동안 숫자·기호 암기
- ② 카드가 A~P 면으로 뒤집힘 (같은 보드 앞/뒤 두 컷)
- ③ 목표 숫자 공개 → 부저
- ④ 5초 안에 **숫자 → 연산자 → 숫자** 순서로 3장
- ⑤ 틀리면 상대에게 기회 (감점 없음)
- **[예시] 계산 규칙** — `9 − 4 = 5` ✓ / `4 − 9` ✕(음수) / `8 ÷ 2 = 4` ✓ / `7 ÷ 2` ✕(나머지)

### 결! 합! 1 · 2
- **목표** 합(3장 세트)을 찾아 점수 · **승리** 라운드 누적 최고점
- **[대표]** 합 타일 3장 + `Checks` (모양 모두 다름 ✓ · 도형 색 모두 같음 ✓ · 배경 모두 다름 ✓)
- ① 속성표 — 모양 / 도형 색 / 배경 색 행에 실제 `HapShape` 견본 (1은 3·3·3, 2는 5·4·3)
- ② 판정: 각 속성마다 "모두 같음" 또는 "모두 다름" — **정답 3장 vs 오답 3장 나란히**, 오답은 "두 개만 같음 ✕" 빨간 표시
- ③ 내 차례 15초 → `합!` → 10초 안에 3장 (세 번째에서 자동 제출) → +1 / −1
- ④ 남은 합이 없다고 생각되면 `결!` → 맞으면 +3, 라운드 종료
- ⑤ 3라운드(3~4인은 인원 수만큼) 누적 점수
- **[예시] 이미 찾은 합** — 같은 3장은 순서를 바꿔도 같은 답 → −1

### 메모리 홀덤
- **목표** 공용 3장 + 내가 고른 2장으로 더 높은 족보 · **승리** 5판 3선승
- **[대표]** 4×4 뒷면 보드 위 내 픽 2칸 강조 + 아래 공용 3장 → 5장 족보 (`PlayingCardFace`)
- ① 진 사람이 선/후공 선택 (첫 판은 동전)
- ② 16장 30초 공개 → 위치 암기
- ③ 뒤집힘 + 공용 카드 3장 공개
- ④ 픽 순서 타임라인: `선 1장 → 후 2장 → 선 1장` (4칸 띠)
- ⑤ 앞면 공개, 족보 비교
- **[예시] 족보 사다리** — 9단계를 미니 카드 예시와 함께 세로로 (신규 `HandRanking`), 아래에 무늬 순위 `♠ > ♦ > ♥ > ♣`

### 아틀라스의 형벌
- **목표** 벌점을 가장 적게 · **승리** 14라운드 후 최저 벌점
- **[대표]** 빨강·초록·파랑 거인 3명, 각자 블록이 쌓인 모습 (`Giant`)
- ① 내 손: 블록 0~6 + 토큰 빨2·초2·파2·무지개1 (8라운드에 다시 받음)
- ② 30초 안에 블록 1 + 토큰 1을 비공개로
- ③ 동시 공개 → **큰 숫자부터** 토큰 색 거인에 올림
- ④ 거인이 무너지면 올린 사람이 **블록 수만큼 벌점**, 무너뜨린 블록만 남음
- ⑤ 맨 먼저 올릴 사람은 패스 가능
- **[예시] 무너짐** — 3컷: `[3,4] 합 7` → `2 올림 → 합 9 ≥ 8` → `벌점 3, 거인에는 [2]만` (`Giant`의 `preview`·`collapsed` 그대로 사용). 인원별 한계 표 `2인 8 · 3인 10 · 4인 12`
- **[예시] 패스 흐름** — 순서도: 내림차순 → 1번째 패스(다음 큰 수부터, 패스한 사람은 맨 끝) → 2번째 패스(오름차순으로 전환) → 더 이상 패스 불가 (신규 `PassFlow`)

- 콜아웃: 라임 원형 번호 배지(①②③)를 그림 위에 절대 위치, 같은 번호를 설명 문장 앞에 붙여 연결
- 정답/오답: 기존 `.passed`/`.failed` 색 재사용 (라임 ✓ / 빨강 ✕)
- 모바일(≤480px): 탭 라벨 축약(`요약 · 순서 · 규칙`), 스텝퍼는 스와이프, 그림은 가로 스크롤 없이 축소
- 애니메이션은 1차에서 하지 않음 (`prefers-reduced-motion` 고려가 필요해지는 시점에 2차로)

## 8. 구현 순서

1. **골격** — `guide/` 폴더, `GameGuide` 타입, `GuideModal`(탭·스텝퍼·아코디언), `initialTab` prop. 기존 규칙 문장을 `rules`로 이전 → 이 시점에 화면은 "전체 규칙" 탭만 채워진 상태로 동일하게 동작
2. **컴포넌트 export 정리** — `HapBoard`/`Checks`/`HapShape`, `Giant`, `PlayingCardFace` export, `Board` 분리
3. **효과 큰 게임부터 그림 채우기** — 결! 합!(그림 없이 이해가 가장 어려움) → 아틀라스(규칙이 가장 많음) → 시크릿 다이스(빠진 규칙 보완) → 나머지
4. **신규 그림** — `CircularStraight`, `PassFlow`, `HandRanking`
5. **검증** — 9개 게임 × 3탭을 데스크톱·모바일(375px)에서 확인, 키보드 ←/→·Esc·탭 이동, 스크린리더 대체 텍스트

1단계는 동작 변화 없는 리팩터링이라 단독 PR로 먼저 내고, 3단계는 게임 2~3개씩 PR을 나누면 리뷰가 쉽습니다.

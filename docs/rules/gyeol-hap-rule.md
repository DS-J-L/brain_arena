# 결! 합! 화면·판정 설계

작성일: 2026-10-26  
상태: 화면·서버 판정·게임 진행·연습 봇·종료 후 복기 구현 완료.

사용자가 정한 규칙을 기본으로 한다. 별도로 명시하지 않은 시간 초과와 단계 전환 동작은 아래의 **구현 기본안**으로 구분한다. 기존 게임의 규칙은 변경하지 않는다.

## 1. 타일과 보드

| 속성 | 종류 |
|---|---|
| 모양 | 원 · 별 · 삼각형 · 사각형 · 해 |
| 도형 색 | 보라 · 녹색 · 주황 · 노랑 |
| 배경 색 | 검정 · 회색 · 하양 |

- 서버가 60가지 조합(5×4×3)에서 서로 다른 타일 9개를 무작위로 뽑는다.
- 3×3 보드에 왼쪽 위부터 행 순서로 1~9 번호를 붙인다.
- 라운드 중에는 타일의 위치·속성·번호를 유지한다. 합을 맞혀도 제거하거나 교체하지 않는다.
- 다음 라운드에는 새로운 보드를 뽑는다. 이전 라운드 타일의 재등장은 허용한다.
- 처음부터 합이 없는 보드도 허용하며 재추첨하지 않는다.
- 별은 오각별, 해는 원형 중심과 여러 개의 분리된 광선으로 그린다. 작은 화면에서도 두 모양의 윤곽을 구별할 수 있어야 한다.

## 2. 화면

```text
┌────────────────────────────────────┐
│ 라운드 1/10     연장일 때: 연장 1   │
│ 나 0점                     상대 0점 │
│ 내 차례                 남은 10초   │
├────────────────────────────────────┤
│   [1 타일]  [2 타일]  [3 타일]     │
│   [4 타일]  [5 타일]  [6 타일]     │
│   [7 타일]  [8 타일]  [9 타일]     │
├────────────────────────────────────┤
│       [ 결! ]       [ 합! ]         │
│ 선택 중: 1 · 3      3개 선택 시 판정 │
│ 판정 결과: 새로운 합 · +1점         │
├────────────────────────────────────┤
│ 이번 라운드에서 찾은 합             │
│ 나: 1·3·7       상대: 2·5·8         │
└────────────────────────────────────┘
```

- 상단에는 라운드, 두 플레이어의 닉네임과 누적 점수, 현재 차례, 서버 마감 시각 기준 남은 시간을 표시한다.
- 모바일에서도 보드는 3열을 유지한다. 타일 번호는 배경색에 맞는 명도로 표시하고, 도형과 겹치지 않게 배치한다.
- 타일에는 모양·도형 색·배경 색을 읽을 수 있는 접근성 이름을 제공한다. 선택 상태는 테두리와 체크 표시로 함께 표현한다.
- `결!`과 `합!`은 보드 바로 아래의 큰 버튼으로 배치한다.
- 선택 모드에서 선택 번호를 표시한다. 세 번째 타일을 클릭하면 즉시 자동 제출하여 서버 판정을 시작하며 별도의 제출 버튼은 없다. 두 개까지는 같은 타일을 다시 눌러 해제할 수 있다. 자동 제출 후에는 결과를 받을 때까지 추가 선택을 막는다.
- 선택 전이나 선택 중에는 정답 여부를 표시하지 않는다. 상대에게 선택 중인 번호를 전송하지 않는다.
- 찾은 합 기록은 양쪽 플레이어가 공유한다. 번호를 오름차순으로 표시하고 발견자도 함께 표시한다.
- 전체 합 개수와 남은 합 개수는 진행 화면에 표시하지 않는다. 결의 판단은 플레이어가 한다.
- 상대 차례, 결과 표시, 라운드 종료, 경기 종료 단계에서는 행동 버튼과 타일 선택을 비활성화한다.

## 3. 합 판정

서로 다른 타일 3개를 골라 **모양·도형 색·배경 색을 각각 따로** 검사한다.

| 한 속성에서 서로 다른 값의 개수 | 의미 | 판정 |
|---|---|---|
| 1 | 세 값이 모두 같음 | 통과 |
| 2 | 두 값만 같고 하나가 다름 | 실패 |
| 3 | 세 값이 모두 다름 | 통과 |

**세 속성이 전부 통과해야 합이다. 속성 하나라도 서로 다른 값의 개수가 2이면 반드시 실패한다.** 전체 속성 종류가 늘어나도 이 기준은 동일하다.

판정 의사 코드:

```ts
function isHap(tiles: Tile[]): boolean {
  if (tiles.length !== 3) return false;
  return ["shape", "shapeColor", "backgroundColor"].every(attribute => {
    const count = new Set(tiles.map(tile => tile[attribute])).size;
    return count === 1 || count === 3;
  });
}
```

이 함수에 전달하기 전에 서버가 **현재 보드의 서로 다른 번호 3개**인지 검증한다. 클라이언트가 보낸 타일 속성이나 판정값을 사용하지 않는다.

| 속성 | A | B | C | 판정 |
|---|---|---|---|---|
| 모양 | 원 | 별 | 해 | 모두 다름: 통과 |
| 도형 색 | 보라 | 보라 | 보라 | 모두 같음: 통과 |
| 배경 색 | 검정 | 회색 | 하양 | 모두 다름: 통과 |

위 조합은 합이다. 도형 색만 `보라·보라·녹색`으로 바꾸면 해당 속성에서 서로 다른 값이 2개가 되어 합이 아니다.

## 4. 전체 합과 중복 처리

1. 보드를 만든 서버가 `1 ≤ a < b < c ≤ 9`인 84가지 조합을 모두 검사한다.
2. 합인 조합을 오름차순 번호 키로 저장한다. 예: `1,3,7`.
3. 이미 찾은 합은 이번 라운드의 공용 집합에 저장한다. 양쪽 플레이어에게 같은 중복 기준을 적용한다.
4. 남은 합은 `전체 합 집합 − 이미 찾은 합 집합`이다.
5. 결은 남은 합 집합의 크기가 0일 때만 정답이다.

`1·3·7`과 `7·1·3`은 같은 답이다. `1·4·8`은 다른 답이며, 조건을 만족하면 1번 타일을 다시 사용해 득점할 수 있다. 라운드가 바뀌면 전체 합과 찾은 합을 모두 새로 설정한다.

**합을 전부 찾았어도 라운드를 자동으로 끝내지 않는다.** 다음 자기 차례의 결 선언으로 +3점을 받을 수 있다. 보드에 처음부터 합이 없으면 첫 차례에 바로 결을 선언할 수 있다.

## 5. 행동과 점수

| 행동 | 점수 변화 | 다음 상태 |
|---|---:|---|
| 자기 차례에 합 클릭 | 없음 | 3개 타일 선택 단계 |
| 새로운 합 제출 | +1 | 기록 후 상대 차례 |
| 합이 아닌 조합 제출 | −1 | 상대 차례 |
| 이미 찾은 합 제출 | −1 | 상대 차례 |
| 결 선언, 남은 합 없음 | +3 | 라운드 종료 |
| 결 선언, 남은 합 있음 | −1 | 상대 차례 |

- 점수는 0점에서 시작하며 음수도 허용한다.
- 합 기록에는 새로운 정답만 추가한다. 오답·중복 제출은 판정 결과로 알린다.
- 한 번의 제출에 점수와 차례 전환을 한 번만 반영한다.
- 형식이 잘못된 요청(번호 범위 밖, 같은 번호 반복, 3개가 아닌 배열)이나 차례 밖 요청은 거부한다. 유효한 3개 조합을 제출한 뒤의 오답 감점과 구분한다.

## 6. 시간과 단계 전환

| 단계 | 제한시간 | 허용 입력 |
|---|---:|---|
| 자기 차례 | 10초 | 결 또는 합 |
| 합 선택 | 5초 | 타일 선택·해제, 세 번째 선택 즉시 자동 제출 |

구현 기본안:

- 합을 누른 요청이 서버에서 승인된 시점부터 별도 5초를 부여한다. 기존 10초의 잔여 시간과 무관하다.
- 합을 누른 뒤에는 결로 바꾸거나 합을 다시 눌러 시간을 초기화할 수 없다.
- 자기 차례의 10초가 지나면 **0점, 패스 1회**로 처리하고 상대 차례로 넘긴다. 별도의 패스 버튼은 두지 않는다.
- 합을 선언하고 5초 안에 제출하지 않으면 **−1점, 상대 차례**로 처리한다. 이는 답변 실패이며 패스 횟수에는 포함하지 않는다.
- 연속 패스 횟수는 양쪽을 합쳐 센다. 합 제출, 합 선택 시간 초과, 결 선언으로 행동이 끝나면 0으로 초기화한다. 합 버튼을 누른 것만으로는 초기화하지 않는다.
- 양쪽 합계 연속 6번 패스하면 보너스 없이 라운드를 종료한다.
- 행동 판정 결과는 1.5초 표시하고 상대의 10초를 시작한다. 라운드 종료 결과는 3초 표시한 뒤 다음 라운드를 시작한다. 표시 시간에는 행동 시간을 차감하지 않는다.
- 선택은 차례가 끝날 때 초기화한다. 재접속해도 서버 마감 시각은 그대로 유지하며 선택 단계에 남아 있으면 남은 시간 안에 다시 선택할 수 있다.

서버 도착 시각이 마감 시각 이상인 요청은 만료된 행동이다. 주기적인 타이머 처리 전에 도착했더라도 마감 이후 요청으로 점수를 얻을 수 없다. 시간 초과와 제출이 겹치면 서버가 한 번만 처리한다.

## 7. 라운드와 승패

- 정답 결 선언 또는 연속 6번 패스로 라운드를 종료한다.
- 정규 경기는 10라운드이며 점수는 누적한다.
- 첫 라운드 선공은 서버가 무작위로 결정한다. 이후 라운드마다 선공을 교대한다.
- 10라운드가 끝났을 때 누적 점수가 높은 플레이어가 승리한다.
- 동점이면 연장 라운드를 진행한다. 구현 기본안으로 연장도 선공을 교대하고, **각 라운드가 끝날 때** 점수가 다르면 경기를 끝낸다. 라운드 도중 일시적으로 앞섰다는 이유로 끝내지 않는다.
- 연장 라운드 종료 후에도 동점이면 같은 방식으로 반복한다.
- 기존 방의 준비·재접속·기권·재대결 흐름을 사용한다.

## 8. 연습 종료 후 복기

연습 모드에서도 합·결 판정은 대전과 동일하다. 기존 연습 대전처럼 봇과 1대1로 진행한다. 봇은 공개 뷰의 보드와 찾은 합만으로 답을 계산하며, 서버의 전체 정답 목록을 전달받지 않는다. 기존 봇의 생각 시간을 사용하고 간헐적으로 추가 시간을 들인다.

- 서버는 각 라운드의 보드와 찾은 합, 제출 기록을 보관한다.
- 연습 종료 후 라운드별로 놓친 합을 모두 표시한다. 정상 결로 끝난 라운드는 놓친 합이 0개다.
- 놓친 합마다 3개 번호와 모양·도형 색·배경 색의 `모두 같음` 또는 `모두 다름` 이유를 보여준다.
- 제출한 오답에는 실패한 속성과 `두 개만 같음` 이유를 표시한다. 중복 답변은 `이미 찾은 합`으로 구분한다.
- 진행 중인 라운드의 전체 정답 목록은 복기 데이터로 미리 전송하지 않는다.

## 9. 서버와 클라이언트의 책임

서버는 보드 생성, 84개 조합 전수 검사, 합 집합, 공용 중복 집합, 점수, 차례, 마감 시각, 패스 횟수, 라운드 종료, 연장과 승패를 관리한다. 클라이언트는 보드와 공개 기록을 렌더링하고 선택 입력을 전달한다.

서버 상태에 필요한 항목:

```text
round / phase / playerIds / firstPlayerId / currentPlayerId
board / allHaps / foundHaps / scores / consecutivePasses
deadline / lastResult / roundHistory / winnerId
```

공개 뷰에는 보드, 점수, 차례, 단계, 마감 시각, 찾은 합과 제출 후 결과를 담는다. `allHaps`와 진행 중 선택 번호는 제외한다. 행동 요청에는 현재 라운드와 `turnId`를 포함해 이전 차례에서 늦게 도착한 요청을 거부한다.

기존 코드에 연결할 위치:

| 영역 | 구현 위치 |
|---|---|
| 게임 식별자·뷰·소개 | `packages/shared/src/types.ts` |
| 판정·진행 엔진과 단위 테스트 | `apps/server/src/games/` |
| 방 시작·입력·타임아웃·공개 뷰 | `apps/server/src/rooms/roomManager.ts` |
| 연습 상대 정책 | `apps/server/src/bots/practiceBot.ts` |
| 게임 화면·결과 복기 | `apps/web/src/pages/RoomPage.tsx` 및 전용 컴포넌트 |
| 게임 내 규칙 안내 | `apps/web/src/components/RuleModal.tsx` |

## 10. 구현·검증 순서

1. 판정 함수, 84개 전체 합 계산, 순서 무관 키와 중복 처리.
2. 서버 점수·차례·마감 시각·패스·라운드·연장 처리.
3. 타일 렌더링, 결·합 버튼, 선택과 제출, 기록과 복기.
4. 엔진 테스트, 방 시스템 연동 테스트, 모바일과 두 플레이어 화면 검증.

| 검증 사례 | 기대 결과 |
|---|---|
| 속성의 서로 다른 값 개수 1 / 3 / 2 | 각각 통과 / 통과 / 실패 |
| 세 속성의 값 개수 조합을 각각 1~3으로 바꾼 27가지 패턴 | 각 값이 모두 1 또는 3인 8가지 패턴만 통과 |
| 원·별·해 / 보라·보라·보라 / 검정·회색·하양 | 합 |
| 위 예시에서 도형 색만 보라·보라·녹색 | 오답, −1점 |
| 보드 9개에서 조합 열거 | 서로 다른 번호의 순서 없는 조합 84개 |
| 1·3·7 정답 후 7·1·3 제출 | 중복, −1점; 상대가 제출해도 동일 |
| 정답에 쓰인 타일이 다른 합에 재사용됨 | 새 합이면 +1점; 보드 유지 |
| 정답 합 하나가 아직 발견되지 않음 | 결 오답, −1점, 상대 차례 |
| 전체 합에서 찾은 합을 제외한 결과가 빈 집합 | 결 정답, +3점, 라운드 종료 |
| 처음부터 전체 합이 없는 보드 | 첫 결 정답, +3점 |
| 마지막 합 제출 | +1점, 상대 차례; 결 자동 처리 없음 |
